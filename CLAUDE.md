# Narada Travels — сайт в дизайне apple.com

## ГЛАВНОЕ ПРАВИЛО

**Сайт делается максимально похожим на apple.com.** Это первично и важнее любых
частных пожеланий по вёрстке.

Отсюда следует, как принимать решения:

1. **Спорные вопросы дизайна решаются замером apple.com, а не вопросом владелице.**
   Она не веб-дизайнер и обратилась именно за тем, чтобы эти решения принимал я.
   Спрашивать можно про контент: какое фото, какой текст, какая цена, что за тур.
   Нельзя спрашивать: «сделать текст поверх фото или под ним», «какая высота
   блока», «какой отступ» — это меряется и решается самостоятельно.
2. **Если она просит что-то, что расходится с дизайном Apple** — сказать об этом
   прямо, показать замер и предложить аппловский вариант. Не выполнять молча.
3. **Никаких значений «на глаз».** Любое число в CSS должно быть либо снято с
   apple.com, либо посчитано (контраст, центр деталей кадра, геометрия).

## Обязательная проверка после каждой правки

```
python3 tools/check.py
```

Меряет ВСЕ блоки на 1440 / 1920 / 2880 и сравнивает с числами apple.com.
Пушить можно только при нуле отклонений. Если отклонение осознанное — оно
вносится в `EXCEPTIONS` внутри check.py **с причиной**, а не оставляется молча.

Инструмент появился потому, что правки шли по одному блоку на глаз: чинили
один — молча ломался соседний, и так по кругу.

## Спецификация (снято с apple.com, WebKit)

Замеры делаются **минимум на двух ширинах** — 1440 и 2880. Числа, снятые на
одной, приводят к поломке на другой: так пропорция плитки 2.18, снятая только
на 2880, на 100% зума превратила плитки в полоски.

| Элемент | Значение | Примечание |
|---|---|---|
| Плитка во всю ширину | высота **692px** | фиксированная, не зависит от окна |
| Плитка сетки | высота **580px** | пропорция — следствие ширины колонки |
| Зазор между плитками | **12px** | по обеим осям |
| Заголовок секции | **56px / 60px** | у нас 64px — допустимо |
| Отступ заголовка от верха плитки | **56px** | у нас `max(56px, nav + 12px)` |
| Подзаголовок секции | **28px** | |
| Заголовок карточки сетки | **40px** | |
| Подзаголовок карточки | **21px** | |
| Потолок ширины контента | **2560px** | `--site-width` |
| Панель навигации | 44px у Apple, **48px** у нас | логотип крупнее |

Все значения живут в `:root` как токены (`--tile-h`, `--card-h`, `--h2`, `--sub`,
`--card-h2`, `--card-sub`, `--card-media-top`, `--grid-gap`, `--nav-h`).
Блоки строятся от токенов, а не от высоты окна: `vh`/`svh` в высотах и отступах
заголовков запрещены — из-за них при зуме заголовки уезжают к середине.

## Архитектура блоков

### Карточка сетки: текст НИКОГДА не лежит на фотографии

У плитки собственный фон (`#f5f5f7` светлая / `#1d1d1f` тёмная), текст лежит
на нём сверху, фотография занимает низ плитки с `--card-media-top`. Они не
пересекаются.

Так сделано у Apple, и причина практическая: **замена фотографии не может
сломать читаемость**. Пока текст лежал на фото, каждая новая картинка требовала
заново подбирать кадр, плотность затемнения и цвет текста — и это был
бесконечный круг.

- Плитки чередуются светлая/тёмная, как в сетке Apple.
- Вид кнопки задаёт тип плитки (`.water-card--dark`), а не класс на карточке.
- Шторка `.water-card__overlay` отключена — она больше не нужна.

### Полноширинные секции (`.tour-section`)

Здесь текст лежит поверх фотографии — как у Apple в крупных плитках. Поэтому:

- Фото: `height: 100%`, `object-fit: cover`, обрезка по краям.
  `contain` запрещён — из-за него изображение сжимается по остатку высоты и
  превращается в марку посреди пустоты.
- Исключение: вырезанные фигуры (`danang-mockup*`) — их резать нельзя, они
  вписываются по высоте. Это записано в EXCEPTIONS.
- Параллакс (`inset: -10%` + GSAP) съедает 14% нижнего края. Если внизу кадра
  есть люди или важное — параллакс для этой секции отключается.
- **При замене фотографии обязательно мерить контраст текста** (скрипт в
  tools/, порог 4.5 для подзаголовка, 3.0 для крупного заголовка). Светлое фото
  требует либо тёмного текста, либо усиленного градиента.

## Мобильная версия

Правится **вместе с десктопом в той же задаче**, а не отдельным заходом.

- Breakpoint основной: 768px. Навигация сворачивается в бургер с 601px.
- Сетка карточек: та же конструкция, что на десктопе (текст на фоне, фото ниже),
  значения меньше: высота `clamp(420px, 62svh, 560px)`, `--card-media-top: 168px`.
- Отступ заголовка привязан к высоте панели: `max(56px, var(--nav-h) + 12px)`.

### Карусель — отдельный breakpoint 600px

| Параметр | Значение |
|---|---|
| `aspect-ratio` карточки | `9/16` |
| `width` карточки | `76vw` |
| `gap` | `16px` |
| `padding` у `.carousel__track` | `0 12vw` |

Контент карточки: `position: absolute; bottom: 24px`, порядок через `order` —
заголовок (1) → описание → кнопка (2).

### Квадратные фото в портретных карточках карусели

`object-position` работает только при overflow. Квадратное фото в портретной
карточке overflow по вертикали не даёт — нужны готовые классы:

| Где субъект | Класс | scale / origin |
|---|---|---|
| Нижняя половина | `carousel__card--sq-low` | 1.5 / center 80% |
| Нижняя треть | `carousel__card--sq-bottom` | 1.8 / center 85% |
| Центр, обрезать нельзя | `carousel__card--sq-fit` | 1.06 / center 96% |

При смене `aspect-ratio` карточки значения пересчитываются.

## Оформление

- Шрифт: SF Pro / -apple-system / BlinkMacSystemFont. Serif запрещены.
- Цвета: `#ffffff`, `#1d1d1f`, `#6e6e73`, `#f5f5f7`, акцент `#0071e3`.
- Кнопки-пилюли `border-radius: 980px`.
- Анимации: `var(--ease)` = `cubic-bezier(0.25, 0.1, 0.25, 1)`, 0.3–0.6s.
  Material-кривые запрещены.
- Тени `box-shadow` с большим spread — нет.
- Навигация фиксированная, `backdrop-filter: blur(20px) saturate(180%)`,
  подложка `rgba(22,22,23,0.8)` во всю ширину экрана.

1. Правка.

3. Замер контраста, если менялись фото или текст поверх них.
4. Агент `apple-reviewer`.
5. `git push` + `open https://cocame.github.io/site` + `open index.html`.
